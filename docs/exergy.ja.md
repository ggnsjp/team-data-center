# エクセルギー：熱の「質」と、計画がそこから読めること

[English](exergy.md)

> **数値はすべてモデルによる推計値です。** 公開データと明示した仮定にもとづくもので、実測値ではありません。需要家ごとの必要温度、需要や候補地の一部は仮定です（[data-sources.md](data-sources.md)、[input-evidence.ja.md](input-evidence.ja.md)）。

このページは、熱の需要家と導管網の温度を選ぶ人に向けたものです。エクセルギーとは何かを説明し、テーマ1の導管網モデルがすでにその考え方に沿っている箇所を示し、公表した計画をエクセルギーで言い直します。表は `uv run python scripts/exergy_balance.py` の出力です。

## 1. エクセルギーとは何か

エネルギーは保存されます。だから「エネルギーを使い切る」とは、エネルギーが消えることではありません。使い切られるのは、仕事をする能力のほうです。この能力を**エクセルギー**（有効エネルギー）と呼びます。あるエネルギーが周囲とつり合うまでに取り出せる仕事の最大量、という定義です [1, 2, 4, 5]。この言葉は1956年に提案されました [3]。

同じ1 kWhでも、中身は違います。

| 1 kWhの | エクセルギー | 理由 |
|---|---|---|
| 電気 | 1 kWh | すべて仕事に換えられる |
| 灯油（発熱量） | 約1 kWh | 燃料の化学エクセルギーは発熱量に近い [1] |
| 30℃の水（石狩の1月、外気−3.2℃） | 0.11 kWh | 周囲との温度差の分しか、エンジンを動かせない |
| 30℃の水（8月、外気22.3℃） | 0.025 kWh | 周囲がほとんど同じ温度 |

絶対温度 $T$ の熱 $Q$ のエクセルギーは、周囲の温度を $T_0$ として、2つの温度のあいだで動く理想的なエンジンの仕事です [1, 2]。

```math
E = Q \left(1 - \frac{T_0}{T}\right)
```

かっこの中がカルノー係数です。熱が周囲と同じ温度ならゼロで、熱が高温になるほど大きくなります。

この上限は熱力学第2法則から出てきます。2つの温度のあいだで動く機関は、可逆なカルノーサイクルの効率を超えられません。熱力学の標準的な演習書は、第2法則の章でカルノーサイクルの効率と最大仕事を扱っています [6]。エクセルギーは、この最大仕事を、周囲を基準にして表した量です [1, 2]。

ここから2つのことが言えます。

- **エネルギーが失われなくても、エクセルギーは現実のどの過程でも失われる。** 燃料のエネルギーの85 %を45℃の水に移す灯油ボイラーは、エネルギーの大半を残しますが、エクセルギーは約12 %しか残しません。必要な温度よりはるかに高温の炎で、ぬるい水をつくっているからです。
- **エネルギーをうまく使うとは、供給の質を需要の質に合わせること。** 低温で足りる需要は低温の熱源でまかない、質の高いエネルギー（電気、燃料）はそれが必要なところに残します。地域熱供給の研究では、これを「質の低い建物の暖房需要」と「排熱や再生可能エネルギーからの質の低い熱供給」を合わせること、と表現しています [7]。第4世代の地域熱供給は導管網の温度を下げるもので、デンマークでは80/40℃から50〜55/25℃へ移行しつつあり [15]、導管の熱損失が減り、低温の熱源を使いやすくなります [8, 9]。スウェーデンとデンマークの事例の分析では、現在の導管網に入れた熱のエクセルギーのほぼ3分の2が配る過程で失われており、温度は下げられる、とされています [10]。

## 2. データセンターの排熱でなぜ大事か

データセンターが使う電気は最後には熱になりますが、その温度は低いです。回収方法のレビューは、難しさを「熱の質が低いこと」だと述べています [11]。モデルの仮定である30℃で計算すると、使える排熱（石狩の4つのデータセンターの合計、シナリオの平均）は年95.7 GWhで、そのうちエクセルギーは6.5 GWh（6.8 %）です。1月は11.0 %、8月は2.5 %です。

この質の熱で蒸気はつくれませんし、高温の用途の熱源としても不向きです。一方で、もともと周囲に近い温度で足りる用途には、ちょうどよい質です。融雪、養殖の水槽、部屋や温室の暖房がそうです。需要が熱源より高温のときは、ヒートポンプが電気を使って温度を上げます。上げる幅が大きいほど、電気が多く要ります。地中に近い温度で運転し、需要家側にヒートポンプを置く導管網は [14] にまとめられています。データセンターの排熱を地域熱供給に入れる事例研究には、フィンランドのエスポー [12] と、バルセロナの空冷データセンター [13] があり、後者では結果が冷却方式で変わります。給湯はレジオネラ対策があるため、低温供給で難しいとされる部分です [15]。エクセルギー解析は、データセンター内部の冷却系にも使われています [16]。

## 3. モデルのどこに入っているか

モデルが最大化するのは金額で、エクセルギーではありません。ただし熱を量だけでなく温度で扱っており、それは次の4か所に入っています。

| 考え方 | モデルでの扱い | 場所 |
|---|---|---|
| 用途ごとに必要な温度がある | 需要家の種類ごとの送り温度：養殖22℃、融雪25℃、プール40℃、温室・学校・公共施設45℃、浴場・病院・ホテル・工場60℃。すべて仮定で、それぞれ理由を付けています | `src/dcopt/heat/network.py` の `SUPPLY_C`、`SUPPLY_BASIS` |
| 温度が足りるなら、そのまま使う | 27℃以下で足りる需要家は、30℃のループの水をヒートポンプなしで使う | `Params.cop`、`direct_margin_k` |
| 温度を上げるには電気が要る（第二法則） | COP = 熱源と必要温度のあいだのカルノーCOPの0.5倍、上限8。45℃で7.95、60℃で4.76。この0.5がヒートポンプ自身のエクセルギー効率にあたり、大型ヒートポンプの実績は理論値の40〜60 %です（[input-evidence.ja.md](input-evidence.ja.md)） | `Params.carnot_cop` |
| 導管網の温度は、全体で判断して決める | 30℃のループ（往き還りの差10 K、損失2 %、需要家側にヒートポンプ）と、60℃の導管網（差30 K、損失8 %、データセンターごとにヒートポンプ。管は細くて済むが、全員が昇温の電気を負担）を比較。期待純便益はループが年93.8百万円、60℃が81.5百万円 | `MODES`、結果は [formulations/heat.md](formulations/heat.md)（英語） |

**モデルが扱っていないもの。** 60℃を超える熱、つまり病院の蒸気や工場のプロセス熱です。モデルは病院・ホテル・工場の年間需要を、全量60℃の水でまかなえる熱として数えています。公表した計画では、この3種が届ける熱の23 %を占めるので、現地でまず確かめるべき仮定です。ほかの不足は5章にあります。

## 4. 公表した計画をエクセルギーで見る

**定義。**

- *基準の状態：* 月ごとの外気（モデルが使っている札幌の月別平年値）。
- *届ける熱*は、需要家が必要とする温度で評価します。$`E_u = Q_u (1 - T_0/T_u)`$。必要以上に高温で送っても、価値は増やしません。
- *電気*は全量を数えます。*排熱*は30℃で、*灯油*は10.17 kWh/Lで数えます（仮定、5章）。
- *エクセルギー効率：* 届けた熱のエクセルギーを、届けるために使ったエクセルギーで割ったもの。

```math
\psi_{\mathrm{boiler}} = \frac{\sum_u E_u}{E_{\mathrm{kerosene}}}
\qquad
\psi_{\mathrm{plan}} = \frac{\sum_u E_u}{W_{\mathrm{electricity}} + E_{\mathrm{waste\ heat}}}
```

**1 MWhを手で計算する。** 公共施設は45℃が必要です。1月の外気は平均−3.2℃です。

- 熱のエクセルギーは 1 − 269.95/318.15 = 0.152 MWh。
- *ボイラー：* 灯油は 1/0.85 = 1.176 MWh（121 L）で、そのエクセルギーは1.233 MWh。効率は 0.152/1.233 = 12.3 %。
- *計画：* ヒートポンプは25℃（30℃のループから温度差5 Kを引いた値）から45℃へ上げるので、COP = 0.5 × 318.15/20 = 7.95。電気は0.126 MWh。残りの0.874 MWhに損失2 %を足した0.892 MWhが排熱で、そのエクセルギーは0.098 MWh。効率は 0.152/(0.126 + 0.098) = 67.8 %。

同じ1 MWhを、需要家の種類ごとに：

| 種類 | 送り温度（℃） | エクセルギー（MWh） | COP | 電気（MWh） | 排熱（MWh） | ボイラー | 計画 |
|---|---|---|---|---|---|---|---|
| 陸上養殖 | 22 | 0.085 | 直接 | 0.000 | 1.020 | 6.9 % | 76.4 % |
| 融雪 | 25 | 0.095 | 直接 | 0.000 | 1.020 | 7.7 % | 84.7 % |
| プール | 40 | 0.138 | 8.00 | 0.125 | 0.893 | 11.2 % | 61.9 % |
| 温室、学校、公共施設 | 45 | 0.152 | 7.95 | 0.126 | 0.892 | 12.3 % | 67.8 % |
| 浴場、病院、ホテル、工場 | 60 | 0.190 | 4.76 | 0.210 | 0.806 | 15.4 % | 63.6 % |

|---|---|---|---|---|---|---|---|---|---|---|

**この数字から言えること。**

- 計画が届ける15,147 MWhのうち、エクセルギーは1,533 MWh（10.1 %）です。需要の質も、熱源と同じく低いのです。
- 灯油ボイラーは、この熱のために燃料のエクセルギーを18,683 MWh使います。エクセルギー効率は8.2 %です。
- 計画が使うのは、電気1,267 MWhと排熱のエクセルギー1,172 MWhで、効率は62.9 %です。買わなければならない質の高いエネルギーは93 %減ります。
- 熱の49 %はヒートポンプの要らない2件に、23 %は昇温幅のいちばん大きい60℃の需要家に届きます。
- 同じ配熱を60℃の導管網で送ると、電気は3,437 MWh（2.7倍）要ります。一部の需要家にしか要らない昇温を、全員の分について行うからです。低温ループのほうが純便益が大きいという結果を、エクセルギーで読むとこうなります。

## 5. この数字の限界

- **モデルの仮定をそのまま引き継いでいます。** 送り温度、年間需要（一部の需要家は仮定）、カルノーCOPの半分というヒートポンプは、モデルの入力であって実測ではありません。
- **電気は受電点で数えています。** 発電で失われるエクセルギーは範囲の外で、灯油の精製と輸送も同じです。あくまで例ですが、電気が効率40 %の火力発電所から来るとすると、その範囲まで広げた計画の効率は約35 %で、それでもボイラーの4倍です。北海道の系統についての数字ではありません。
- **基準の状態は外気の月平均です。** 1日の中の変化は見ていません。夏の低温利用は、この測り方ではエクセルギーがほぼゼロになります。冷たい原水を温める養殖は、過小に評価されます。
- **熱は1つの温度（送り温度）で評価しています。** 往きから還りまで冷えていく幅は見ていません。ループを30℃と20℃の平均で評価すれば、排熱のエクセルギーは小さくなり、計画の効率は上がります。
- **ポンプ動力はモデルに入っていません。** 往き還りの差が10 Kのループは、30 Kの導管網の約3倍の水を動かすので、入れると計画の効率はいくらか下がります。
- **灯油のエクセルギーは仮定です。** 燃料の化学エクセルギーは、ふつう低位発熱量に組成で決まる比を掛けて表します [1]。その比は計算せず、高位発熱量の10.17 kWh/L（低位の1.065倍。標準発熱量は [input-evidence.ja.md](input-evidence.ja.md)）を使いました。モデルの9.7 kWh/Lを使うと、ボイラーの効率は8.2 %ではなく8.6 %になります。
- **60℃方式の列は、配熱先を固定した比較です。** 60℃の導管網向けに最適化し直した計画ではありません。最適化した比較は、3章の93.8対81.5百万円です。
- **エクセルギーは費用のモデルの代わりにはなりません。** 金額の結果がなぜそうなるかを説明し、質がどこで無駄になっているかを示すものです。判断は、費用、リスク、誰が払うかで決まります。

## 6. 次にやること

- 病院・ホテル・工場の需要を温度帯（蒸気、給湯、暖房）で分け、導管網でまかなえる分だけを数える。
- 蓄熱槽（一定の熱源と、山のある需要のあいだの時間差を埋める）とポンプ動力を入れる。
- 導管網の温度を2択から広げる。高温の需要家から低温の需要家へ順に使うカスケードも含める。
- アプリで、金額の横にエクセルギー効率を表示する。

## 7. 再現

```
uv run python scripts/export_heat_network_v2.py     # out/heat_network_v2/plans.json がないとき
uv run python scripts/exergy_balance.py             # 4章の表
```

計算は `src/dcopt/heat/exergy.py` にあります。`tests/test_exergy.py` は、手計算の例を確かめ、エクスポートがあるときはこのページの数字がそれと一致することも確かめます。
